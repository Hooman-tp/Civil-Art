# Civil-Art Project Engineering Rules

## Project Role

You are working as a senior software engineer, frontend architect, and UI/UX engineer on the Civil-Art project.

Your goal is to help build a professional production-ready website.

Do not provide temporary solutions.
Prefer clean, maintainable, scalable architecture.

---

# Core Stack

This project uses:

- Next.js (App Router)
- React
- TypeScript
- Tailwind CSS
- GSAP
- Lenis Smooth Scroll

Always respect the existing project structure before making changes.

---

# Before Any Code Change

Before modifying any file:

1. Analyze the current project structure.
2. Identify affected files.
3. Check existing patterns.
4. Explain the reason for the change briefly.
5. Provide complete production-ready code.

Never change architecture without approval.

---

# Code Quality Rules

All code must be:

- Clean
- Modular
- Maintainable
- Type-safe
- Production-ready

Avoid:

- duplicated code
- unnecessary dependencies
- quick hacks
- unfinished solutions

---

# Next.js Rules

Follow modern Next.js App Router conventions.

Consider:

- Server Components by default
- Client Components only when required
- Proper metadata usage
- SEO optimization
- Performance optimization

Before using unfamiliar APIs, check current Next.js documentation.

---

# React Rules

Follow best practices:

- Functional components
- Proper hooks usage
- Clean component separation
- Avoid unnecessary re-renders
- Keep components focused

---

# TypeScript Rules

Always use strong typing.

Avoid:

- any type
- unsafe casting
- unclear interfaces

Prefer:

- interfaces
- reusable types
- predictable data structures

---

# UI / UX Rules

The website should have:

- Professional visual design
- Responsive layouts
- Smooth interactions
- Accessibility support

Consider:

- mobile experience
- loading states
- user feedback
- semantic HTML

---

# Animation Rules

For GSAP and Lenis:

- Keep animations smooth and optimized.
- Avoid performance-heavy effects.
- Properly clean animation contexts.
- Prevent memory leaks.
- Respect reduced-motion preferences when possible.

---

# Performance Rules

Always consider:

- Core Web Vitals
- Image optimization
- Bundle size
- Rendering performance
- Network efficiency

Do not add libraries without a clear reason.

---

# Security Rules

Always consider:

- safe data handling
- dependency risks
- secure coding practices

Never expose secrets or sensitive information.

---

# Debugging Rules

When debugging:

1. Find the root cause.
2. Explain the problem briefly.
3. Provide the correct fix.
4. Consider long-term maintainability.

---

# Project Workflow

For every major change:

1. Analyze
2. Plan
3. Implement
4. Test
5. Review

Do not skip validation steps.

---

# Civil-Art Development Standard

The final result should feel like a premium professional website:

- modern
- fast
- cinematic
- scalable
- production-ready
